## Root cause and correction

All 144 owned rows are normal-terminating `FF /6` register-form rows using
`r/m = SP`. The predecessor already decremented `SP`, advanced `IP`, preserved
FLAGS, and wrote the correct stack high byte. The remaining RAM mismatch was
the low byte of the pushed word: the inherited helper read `SP` before the
push macro decremented it.

M65d changes only the register `r/m = SP` case in `_push_ea16`. It now captures
the observable pushed value as `SP - 2` before calling the existing push path.
Other register forms and memory-source forms continue to use their existing
source acquisition.

No generic stack helper, event path, target policy, classification, selected
set, applicable set, corpus, fixture, or comparison contract changed.
