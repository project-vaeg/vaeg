operand at or above `0xa0000`. Those paths are therefore protected as
non-owned `F7 /2` behavior, not used as the root-cause authority for this
fix.

## Root cause and correction

Root-cause classification:
`f7_not_word_write_path`

The active `_not_ea16` memory fast path used:

```c
*(mem + madr) ^= 0xffff;
```

`mem` is a byte pointer, so this operation updated only the low byte at
`madr`. The high byte remained unchanged. That exactly matches the M65c
predecessor failure signature.

M65c changes only the `F7 /2` word NOT fast path. It now loads the 16-bit
little-endian value, complements all 16 bits, and stores the complete word
back using the existing Intel-endian helpers. The inhibited word path already
used `i286_memoryread_w` / `i286_memorywrite_w` and remains unchanged.

M65c does not change generic effective-address calculation, generic memory
mapping, register-form `F7 /2`, C6/C7, FF `/7`, BOUND, FF `/6`, the exact
ten-case tail, target policy, classifications, selected sets, applicable
sets, SST fixtures, or comparison contracts.
