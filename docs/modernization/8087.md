# Intel 8087 implementation

This document is the implementation-level companion to the v7 8087 contract.
It records the software boundary, the VA2/VA3 integration policy, and the
hardware-informed default clock. It does not claim that the unresolved VA2
PCB BUSY/INT traces have been physically identified.

## Clock policy

The active default is **8,000,000 Hz**. The policy was amended from the
original 10 MHz emulator default after the VA2 field report
[PC-88VA2への数値演算プロセッサ(8087-2)増設](https://ameblo.jp/framgate/entry-12146188742.html).
That report identifies the installed 8087-2 as an 8 MHz grade and reports an
oscilloscope measurement of 8 MHz on the VA2 socket's pin 19 clock. This is
useful board-level evidence for the default, but it is not a universal
schematic or PCB-routing proof for every VA2/VA3 unit.

The emulator continues to accept integer frequencies from 1,000,000 through
20,000,000 Hz. The 5 MHz, 8 MHz, and 10 MHz presets remain available, so an
8087-1 or a board with a different measured clock can be selected explicitly.
The configured value is stored in `vaeg.cfg` as `NDP8087Hz` and becomes active
at machine reset; changing the GUI field does not change a running NDP.

## Device and model boundary

- `machine/pccore.c` owns the single machine-level `UPD8087_STATE` instance.
- The device can be enabled only for the VA2/VA3 model profile. VA1 and FPO2
  do not receive an 8087, and no second NDP slot or queue is created.
- The SDL2 startup menu exposes `VA`, `VA2/VA3`, and `VA2/VA3 + 8087`. The
  Configure dialog exposes enable state, the active/requested clock, and the
  reset-required boundary.
- Configuration and the 8087 machine-state section preserve the clock,
  service residue, BUSY state, pending exception, control/status/tag words,
  raw 80-bit registers, and environment/save images.

## CPU/NDP seam

`cpu/upd9002/` keeps native V30/uPD9002 decoding separate from the
uPD70008-compatible path. In native mode, documented `D8`–`DF` ESC forms enter
the production 8087 adapter only when the optional device is enabled. The
native `0x66` FPO2/reserved path and the compatibility path do not reach this
NDP. Disabled-device ESC bytes still pass through the native CPU's byte and
effective-address rules without inventing a bus device.

The 8087 core in `cpu/upd8087/` classifies every D8–DF ModR/M slot, performs
the documented memory and register forms, and handles packed BCD,
environment/save/restore, control and exception instructions, integer
transfers, and the five required transcendental operations. Architectural
values cross the core boundary as the explicit raw 80-bit representation;
new runtime code does not use host floating point.

Arithmetic is supplied by the exact Berkeley SoftFloat Release 3e material
recorded under `external/softfloat/` and its v7 provenance records. The core
does not import an x87 implementation from another emulator or silently
adopt later-x87 behavior.

## Timing and exceptions

The first timing model is `SERIAL_TIMED_V1`. Each instruction obtains its
documented/contracted NDP service-cycle count, converts it with checked integer
accounting, and carries the fractional residue:

```text
numerator     = ndp_cycles * cpu_clock_hz + service_remainder
cpu_ticks     = numerator // ndp_clock_hz
next_remainder = numerator % ndp_clock_hz
```

Consequently, 100 NDP clocks at the new default 8 MHz consume 12.5 scheduler
microseconds when the scheduler timebase is 1 MHz; the residue is retained
instead of rounded independently per instruction. The configured frequency
therefore affects emulated NDP service time, not just the displayed GUI value.

The software exception path exposes the NDP source to the existing PIC model,
supports guest acknowledgement/EOI behavior, and keeps FWAIT/POLL behavior
separate from an absent device. The actual VA2 PCB BUSY pin connection,
active polarity, physical INT route, PIC input mode, and board vector remain
unresolved hardware evidence. They are tracked under
[Issue #8](https://github.com/nakatamaho/vaeg/issues/8); the software tests do
not promote that issue to a physical wiring claim.

## Verification boundary

The focused 8087 core tests cover the 8 MHz default, custom clock conversion,
reset-time application, residue persistence, state codecs, instruction
inventory, and service-time changes. Production selftests cover the native
CPU seam, the one-device/FPO2 boundary, guest interrupt behavior, PIC input
modes, and savestate restoration. Existing VA2 BASIC runs that explicitly
used `NDP8087Hz=10000000` remain valid as custom-frequency evidence; they are
not evidence that 10 MHz is the default.

P17/P19 remain integration-blocked until the physical VA2 BUSY/INT route is
verified independently.
